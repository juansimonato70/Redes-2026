11.1 Conmutadores y Enrutadores de Cisco

11.1.0 Introducción

Los conmutadores (switches) y enrutadores (routers) de Cisco son dispositivos fundamentales en las redes modernas. Comprender su funcionamiento, configuración y proceso de arranque es esencial para administrar y solucionar problemas en infraestructuras de red.

Diferencias Fundamentales: Switch vs Router

  • Switch (Conmutador):
    • Opera en Capa 2 (Enlace de Datos)
    • Conecta dispositivos en la MISMA red local (LAN)
    • Usa direcciones MAC para reenviar tramas
    • Crea dominios de colisión separados
    • Todos los puertos en el mismo dominio de broadcast (por defecto)
  • Router (Enrutador):
    • Opera en Capa 3 (Red)
    • Conecta DIFERENTES redes (LANs, WANs, Internet)
    • Usa direcciones IP para enrutar paquetes
    • Separa dominios de broadcast
    • Toma decisiones de enrutamiento basadas en tablas de routing
Analogía:

• Switch: Como un edificio de oficinas - conecta habitaciones (dispositivos) en el mismo piso (red local)
• Router: Como una central de correos - conecta diferentes edificios/ciudades (redes diferentes)

11.1.1 Conmutadores Cisco

Los switches Cisco son dispositivos de red que operan principalmente en la Capa 2 del modelo OSI, aunque existen switches de capa 3 (multilayer switches) que también pueden enrutar.

Un switch físico real: cada puerto conecta un dispositivo distinto de la red

Componentes Principales de un Switch Cisco

  • CPU: Procesa comandos, routing (en L3), protocolos (STP, VTP, etc.)
  • RAM: Almacena running-config, tabla MAC, tabla ARP, buffers de paquetes
  • Flash: Almacena IOS (sistema operativo), archivos de configuración de backup
  • NVRAM: Almacena startup-config (configuración que se carga al arrancar)
  • ASIC (Application-Specific Integrated Circuit): Hardware especializado para conmutación a velocidad de cable
  • Puertos: Interfaces físicas RJ-45 (Ethernet), SFP (fibra), consola
  • LEDs: Indicadores de estado, link, speed, PoE, modo
  • Fuente de alimentación: Interna o redundante (switches empresariales)

Acceso y Configuración Inicial

Métodos de Acceso al Switch:

  1. Puerto de Consola (más común para configuración inicial):
    • Cable consola RJ-45 a DB-9 o USB
    • Software: PuTTY, Tera Term, SecureCRT, minicom
    • Configuración: 9600 baud, 8 data bits, no parity, 1 stop bit, no flow control
    • Acceso directo sin necesidad de red
  2. SSH (Secure Shell - recomendado):
    • Requiere configuración previa de IP, usuario, contraseña
    • Cifrado, seguro
    • Puerto TCP 22
  3. Telnet (inseguro, NO recomendado):
    • Sin cifrado - contraseñas en texto plano
    • Puerto TCP 23
    • Solo para redes de laboratorio/práctica
# Configuración básica inicial de un switch Cisco

Switch> enable # Entrar a modo privilegiado
Switch# configure terminal # Modo configuración global

# Configurar nombre del switch
Switch(config)# hostname SW-Oficina-1

# Configurar contraseña de enable (modo privilegiado)
SW-Oficina-1(config)# enable secret Cisco123!

# Configurar línea de consola
SW-Oficina-1(config)# line console 0
SW-Oficina-1(config-line)# password ConsolaPass
SW-Oficina-1(config-line)# login
SW-Oficina-1(config-line)# logging synchronous # Evita interrupciones de mensajes
SW-Oficina-1(config-line)# exit

# Configurar IP de gestión (VLAN 1 por defecto)
SW-Oficina-1(config)# interface vlan 1
SW-Oficina-1(config-if)# ip address 192.168.1.10 255.255.255.0
SW-Oficina-1(config-if)# no shutdown
SW-Oficina-1(config-if)# exit

# Configurar gateway predeterminado
SW-Oficina-1(config)# ip default-gateway 192.168.1.1

# Guardar configuración
SW-Oficina-1(config)# exit
SW-Oficina-1# copy running-config startup-config
o
SW-Oficina-1# write memory # Comando abreviado
Running-Config vs Startup-Config:

• running-config: Configuración activa en RAM (se pierde al reiniciar)
• startup-config: Configuración guardada en NVRAM (persiste tras reinicio)

IMPORTANTE: Los cambios se aplican inmediatamente en running-config, pero NO se guardan automáticamente. Siempre ejecutar copy run start o write después de configurar.

Auto-Negociación

Los switches modernos usan auto-negociación para determinar automáticamente:

  • Velocidad: 10/100/1000 Mbps (según capacidades de ambos lados)
  • Duplex: Half-duplex o Full-duplex
  • Proceso: Mediante Fast Link Pulses (FLP)

Configuración recomendada: Auto/Auto en ambos lados (switch y dispositivo)

Duplex Mismatch - Problema Común:

Ocurre cuando un lado está en auto y el otro en configuración fija (hard-coded):

• Síntoma: Conexión muy lenta, muchos errores, timeouts
• Causa: Switch A: auto/auto | Dispositivo B: 100/full (fijo)
• Resultado: Switch detecta velocidad (100) pero NO puede negociar duplex
  - Switch cae a HALF-duplex (valor por defecto)
  - Dispositivo está en FULL-duplex
  - DUPLEX MISMATCH → colisiones constantes

Solución:
• Opción 1: Ambos en auto/auto (RECOMENDADO)
• Opción 2: Ambos con valores fijos iguales (100/full en ambos)
# Ver estado de interfaz
Switch# show interface gigabitethernet 0/1
Switch# show interface status # Resumen de todos los puertos

# Configurar velocidad y duplex (si es necesario)
Switch(config)# interface gigabitethernet 0/1
Switch(config-if)# speed auto # o 10, 100, 1000
Switch(config-if)# duplex auto # o half, full

# Verificar errores en interfaz
Switch# show interface gigabitethernet 0/1 | include error

Métodos de Reenvío (Switching Methods)

Los switches pueden usar diferentes métodos para reenviar tramas. Cada método tiene diferentes compromisos entre velocidad y confiabilidad:

Método Descripción Latencia Confiabilidad
Store-and-Forward Recibe trama completa, verifica CRC, luego reenvía Alta Alta (descarta tramas corruptas)
Cut-Through Comienza a reenviar apenas lee MAC destino (6 bytes) Muy baja Baja (puede reenviar tramas corruptas)
Fragment-Free Lee primeros 64 bytes (mínimo Ethernet), luego reenvía Media Media (elimina runts y fragments)

1. Store-and-Forward (Más Común)

  • Proceso:
    1. Recibe la trama COMPLETA en buffer
    2. Verifica CRC (Frame Check Sequence)
    3. Si CRC OK → reenvía trama al destino
    4. Si CRC error → descarta trama
  • Ventajas:
    • Mayor confiabilidad - no propaga errores
    • Permite conectar puertos de diferentes velocidades
    • Puede almacenar en búfer si destino está ocupado
  • Desventajas: Mayor latencia (microsegundos adicionales)
  • Uso: Switches empresariales modernos, método ESTÁNDAR

2. Cut-Through (Corte Directo)

  • Proceso:
    1. Lee solo los primeros 6 bytes (MAC destino)
    2. Consulta tabla MAC
    3. Comienza a reenviar INMEDIATAMENTE
    4. No espera el resto de la trama ni verifica CRC
  • Ventajas: Latencia ultra-baja (importante en trading financiero, gaming)
  • Desventajas:
    • Puede reenviar tramas corruptas
    • Solo funciona si puertos tienen la misma velocidad
  • Uso: Switches especializados de baja latencia

3. Fragment-Free (Libre de Fragmentos)

  • Proceso:
    1. Lee los primeros 64 bytes de la trama
    2. Esto cubre la "collision window" (ventana de colisión)
    3. Si pasa 64 bytes sin error, probablemente esté bien
    4. Reenvía el resto sin esperar
  • Ventajas: Baja latencia + elimina runts (tramas < 64 bytes)
  • Desventajas: Aún puede reenviar algunas tramas corruptas
  • Uso: Híbrido entre store-and-forward y cut-through
¿Cuál método usa mi switch?

• La mayoría de los switches Cisco modernos usan Store-and-Forward exclusivamente
• Algunos switches empresariales de alta gama ofrecen opción de Cut-Through
• Fragment-Free es menos común hoy en día

En redes modernas full-duplex sin colisiones, store-and-forward es suficiente y preferido.

Memoria Búfer en Switches

Los switches usan memoria búfer (buffer) para manejar diferencias de velocidad y tráfico burst:

  • Port-Based Memory: Cada puerto tiene búfer dedicado
  • Shared Memory: Pool de memoria compartido por todos los puertos (más eficiente)

Problema de congestión: Si búfer se llena → tramas descartadas (tail drop)

11.1.3 Proceso de Arranque del Conmutador

Cuando un switch Cisco se enciende, pasa por una secuencia específica de pasos para iniciarse correctamente:

Secuencia de Arranque (Boot Sequence)

  1. Power-On Self Test (POST)
    • El switch ejecuta pruebas de hardware al encenderse
    • Verifica: CPU, DRAM, Flash, interfaces
    • LED del sistema: Ámbar durante POST
    • Si POST falla: LED permanece ámbar (problema de hardware)
    • Si POST OK: LED cambia a verde, continúa arranque
    • Duración típica: 5-10 segundos
  2. Carga del Boot Loader
    • Pequeño programa en ROM que inicia el sistema
    • Inicializa el sistema de archivos flash
    • Localiza y carga el IOS
  3. Carga del IOS (Internetwork Operating System)
    • El boot loader carga la imagen IOS desde Flash
    • Descomprime el IOS en RAM
    • Imagen típica: c2960-lanbasek9-mz.150-2.SE11.bin
    • IOS se ejecuta desde RAM
    • Duración: 20-60 segundos (depende del modelo)
  4. Inicialización del IOS
    • IOS inicializa todas las interfaces
    • Detecta hardware instalado
    • Crea tabla MAC vacía
  5. Carga de la Configuración
    • IOS busca archivo startup-config en NVRAM
    • Si existe: carga startup-config en RAM como running-config
    • Si NO existe: entra en modo Setup (configuración inicial) o modo EXEC directamente
  6. Switch Operacional
    • Switch totalmente funcional
    • Presenta prompt de CLI (consola)
    • Listo para aceptar comandos
    • Tiempo total de arranque: ~1-2 minutos

Recuperación de Contraseña del Switch:

Si olvidas la contraseña de enable, puedes recuperar el acceso:

1. Conectar cable de consola
2. Apagar el switch, encenderlo mientras mantienes presionado el botón MODE
3. Entrar al modo ROMMON (boot loader)
4. Ejecutar: flash_init
5. Renombrar/borrar el archivo de configuración: rename flash:config.text flash:config.old
6. Reiniciar: boot
7. El switch arranca sin configuración (sin contraseña)
8. Recuperar config antigua: rename flash:config.old flash:config.text
9. Cargarla: copy flash:config.text running-config
10. Cambiar contraseña: enable secret NuevaContraseña
11. Guardar: copy run start

Nota de seguridad: Esto demuestra por qué la seguridad física es importante.

11.1.4 Enrutadores Cisco

Los routers Cisco son dispositivos de Capa 3 que conectan diferentes redes y toman decisiones de enrutamiento basadas en direcciones IP.

Un router real: conecta redes distintas y enruta el tráfico entre ellas

Series de Routers Cisco Populares

Serie Tipo Interfaces Típicas Uso Principal
ISR 800 Series Branch pequeño 4-8 puertos Fast Ethernet Oficinas pequeñas, retail
ISR 1000 Series Branch moderno Gigabit Ethernet, WiFi integrado Sucursales SD-WAN
ISR 4000 Series Enterprise Modular, Gigabit/10G Sucursales grandes, WAN
ASR 1000 Series Aggregation 10G/40G/100G WAN edge, data center edge
ASR 9000 Series Core/SP 100G/400G, altísima capacidad Service Providers, core Internet

Componentes Principales de un Router Cisco

  • CPU: Procesa paquetes, ejecuta protocolos de routing (OSPF, EIGRP, BGP), toma decisiones
  • RAM: Almacena:
    • Running-config (configuración activa)
    • Tabla de routing (routing table)
    • Tabla ARP
    • Caché de conmutación rápida
    • Buffers de paquetes
  • Flash: Almacena imagen del IOS, archivos de configuración de backup
  • NVRAM: Almacena startup-config (persiste tras reinicio)
  • ROM: Almacena:
    • Bootstrap (boot loader)
    • POST (Power-On Self Test)
    • Mini-IOS (ROMMON - para recuperación)
  • Interfaces:
    • WAN: Serial, T1/E1, DSL, Cable, Fibra
    • LAN: Ethernet (RJ-45), SFP (fibra)
    • Gestión: Console, AUX (acceso remoto por módem - legacy)

Tipos de Interfaces en Routers

1. Interfaces LAN (Ethernet)

  • Nomenclatura: FastEthernet 0/0, GigabitEthernet 0/0/0
  • Propósito: Conectar redes locales
  • Características: Auto-negociación, full-duplex, hot-swappable (SFP)

2. Interfaces WAN

  • Serial: Conexiones punto a punto (legacy, T1/E1)
  • GigabitEthernet WAN: Conexión a internet/MPLS moderna
  • Cellular: 4G/5G backup/primario
  • DSL/Cable: Internet de banda ancha
# Configuración básica de interfaz de router

Router(config)# interface gigabitethernet 0/0
Router(config-if)# description LAN Oficina Principal
Router(config-if)# ip address 192.168.1.1 255.255.255.0
Router(config-if)# no shutdown # Activar interfaz
Router(config-if)# exit

Router(config)# interface gigabitethernet 0/1
Router(config-if)# description WAN - ISP
Router(config-if)# ip address 200.50.10.2 255.255.255.252
Router(config-if)# no shutdown

# Configurar ruta estática por defecto (a Internet)
Router(config)# ip route 0.0.0.0 0.0.0.0 200.50.10.1

# Guardar configuración
Router# copy running-config startup-config
Diferencia clave: Interfaces de Router vs Switch

Router:
• Interfaces están administrativamente down por defecto
• Requieren comando no shutdown para activarse
• DEBEN tener dirección IP configurada para funcionar

Switch:
• Interfaces están activas por defecto (no shutdown)
• No requieren IP en cada puerto (solo VLAN de gestión)
• Funcionan en Capa 2 (MAC) sin necesidad de IP

11.1.5 Proceso de Arranque del Enrutador

El proceso de arranque de un router Cisco es similar al de un switch, pero con algunas diferencias importantes:

Secuencia de Arranque del Router

  1. Power-On Self Test (POST)
    • Ejecuta diagnósticos de hardware
    • Verifica: CPU, memoria, interfaces
    • Mensajes en consola: "System Bootstrap, Version..."
    • Si falla: Router no arranca, queda en ROMMON
  2. Carga del Bootstrap (Boot Loader)
    • Programa en ROM que localiza el IOS
    • Lee el registro de configuración (config-register)
    • Valor típico: 0x2102 (arranque normal)
    • Determina CÓMO y DE DÓNDE cargar el IOS
  3. Localización del IOS
    • Bootstrap busca imagen IOS según config-register:
    • 0x2102: Buscar en Flash (normal)
    • 0x2101: Arrancar desde ROMMON (modo recuperación)
    • Lee variable de boot: boot system flash:c2900-universalk9-mz.SPA.157-3.M5.bin
  4. Carga del IOS en RAM
    • Copia imagen desde Flash a RAM
    • Descomprime el IOS
    • IOS se ejecuta desde RAM (más rápido)
    • Mensajes: "Loading image...", "###..." (barra de progreso)
  5. Búsqueda de Configuración
    • IOS busca archivo de configuración en este orden:
    • 1º: NVRAM (startup-config) - UBICACIÓN NORMAL
    • 2º: Servidor TFTP (si está configurado)
    • Si NO encuentra: entra en modo Setup (dialog inicial)
  6. Ejecución de la Configuración
    • Carga startup-config en RAM como running-config
    • Ejecuta comandos línea por línea
    • Configura hostname, interfaces, routing, etc.
  7. Router Operacional
    • Presenta el prompt CLI: Router> o Router#
    • Interfaces configuradas activas
    • Protocolos de routing iniciados
    • Listo para enrutar tráfico
# Ver registro de configuración
Router# show version # Al final muestra config-register

# Cambiar registro de configuración
Router(config)# config-register 0x2102 # Arranque normal
Router(config)# config-register 0x2142 # Ignorar startup-config (recuperación)

# Configurar imagen de boot específica
Router(config)# boot system flash:c2900-universalk9-mz.bin

# Ver secuencia de boot configurada
Router# show boot
Router# show flash # Ver archivos en Flash

Valores del Registro de Configuración

Valor Descripción Uso
0x2102 Arranque normal desde Flash, carga startup-config Operación normal (PREDETERMINADO)
0x2142 Arranque desde Flash, IGNORA startup-config Recuperación de contraseña
0x2101 Arranque en modo ROMMON (mini-IOS en ROM) Recuperación de IOS corrupto
Recuperación de Contraseña del Router:

Procedimiento detallado:

1. Reiniciar router y enviar break
• Reiniciar: reload o apagar/encender
• Durante los primeros 60 segundos, presionar Ctrl+Break (o Break en terminal)
• Entra en modo ROMMON: rommon 1 >

2. Cambiar config-register para ignorar startup-config
rommon 1 > confreg 0x2142
rommon 2 > reset

3. Router arranca sin configuración (sin contraseña)
• Entrar al router (sin contraseña)
• Modo privilegiado: enable (sin password)

4. Copiar startup-config a running-config
Router# copy startup-config running-config
• Ahora tienes la configuración original (excepto contraseñas que no funcionan)

5. Cambiar contraseña
Router# configure terminal
Router(config)# enable secret NuevaPassword123

6. Restaurar config-register normal
Router(config)# config-register 0x2102
Router(config)# exit

7. Guardar configuración
Router# copy running-config startup-config

8. Reiniciar
Router# reload

¡Router recuperado con nueva contraseña!
Modo ROMMON (ROM Monitor):

Es un mini-sistema operativo en ROM para recuperación:

• Cuándo se usa:
  - IOS corrupto/borrado
  - Recuperación de contraseña
  - Cambio de config-register
  - Carga de nuevo IOS vía TFTP

• Comandos útiles en ROMMON:
confreg - Cambiar config-register
reset - Reiniciar router
boot - Intentar arrancar IOS
tftpdnld - Descargar IOS desde servidor TFTP
dir flash: - Ver archivos en Flash

• Cómo entrar:
  - Ctrl+Break durante arranque
  - Config-register 0x2101
  - Automáticamente si no hay IOS válido

11.2 Solución de Problemas Comunes de Red

11.2.0 Introducción

La solución de problemas (troubleshooting) es una habilidad fundamental para cualquier profesional de redes. Implica identificar, diagnosticar y resolver problemas de conectividad y rendimiento de manera sistemática y eficiente.

Principios Fundamentales del Troubleshooting

  • Metodología sistemática: Seguir un proceso lógico y estructurado
  • Recopilación de información: Obtener todos los datos relevantes antes de actuar
  • Dividir y conquistar: Aislar el problema en una capa o componente específico
  • Cambiar una variable a la vez: No hacer múltiples cambios simultáneos
  • Documentar: Registrar síntomas, pruebas realizadas y soluciones aplicadas
  • Verificar la solución: Confirmar que el problema está resuelto completamente

11.2.1 El Proceso para Solucionar Problemas

Existen varios enfoques para solucionar problemas de red. Los más comunes se basan en el modelo OSI:

Métodos de Troubleshooting

1. Enfoque Bottom-Up (De Abajo Hacia Arriba)

Comienza en la Capa 1 (Física) y sube hasta la Capa 7 (Aplicación)

  • Proceso: Física → Enlace → Red → Transporte → Aplicación
  • Ventaja: Metódico, encuentra problemas de hardware primero
  • Desventaja: Puede ser lento si el problema está en capas superiores
  • Mejor para: Problemas de conectividad física, redes nuevas

2. Enfoque Top-Down (De Arriba Hacia Abajo)

Comienza en la Capa 7 (Aplicación) y baja hasta la Capa 1 (Física)

  • Proceso: Aplicación → Transporte → Red → Enlace → Física
  • Ventaja: Identifica rápido problemas de aplicación/configuración
  • Desventaja: Puede pasar por alto problemas físicos obvios
  • Mejor para: Problemas de software, aplicaciones específicas

3. Enfoque Divide and Conquer (Dividir y Conquistar)

Comienza en una capa intermedia (típicamente Capa 3) y ajusta según resultados

  • Proceso: Probar conectividad IP (ping), si falla → bajar capas, si funciona → subir capas
  • Ventaja: Más eficiente, reduce pasos de troubleshooting
  • Desventaja: Requiere más experiencia para elegir el punto de inicio correcto
  • Mejor para: Técnicos experimentados, problemas generales

4. Enfoque Follow the Path (Seguir la Ruta)

Seguir físicamente la ruta de los datos desde origen hasta destino

  • Proceso: PC → Switch → Router → Internet → Servidor
  • Ventaja: Intuitivo, fácil de entender
  • Desventaja: Puede ser lento en redes complejas
  • Mejor para: Entrenar nuevos técnicos, redes pequeñas

5. Enfoque Spot the Differences (Detectar Diferencias)

Comparar configuración/estado actual vs configuración/estado funcional conocido

  • Proceso: "Funcionaba ayer, hoy no" → ¿Qué cambió?
  • Ventaja: Muy efectivo cuando hay un estado de referencia
  • Desventaja: Requiere documentación/backups de configuraciones
  • Mejor para: Problemas que aparecieron súbitamente

Metodología de 7 Pasos (Recomendada)

  1. Definir el problema
    • Reunir información: ¿Qué exactamente no funciona?
    • Identificar síntomas: ¿Cuándo comenzó? ¿A quién afecta?
    • Determinar alcance: ¿Un usuario, un departamento, toda la red?
    • Hacer preguntas clave: "¿Funcionó alguna vez? ¿Qué cambió?"
  2. Recopilar información
    • Revisar logs del sistema
    • Verificar configuraciones
    • Revisar documentación de red
    • Hablar con usuarios afectados
    • Revisar cambios recientes (tickets, change management)
  3. Analizar información
    • Identificar patrones en síntomas
    • Consultar knowledge base / documentación
    • Relacionar con el modelo OSI
    • Formular hipótesis iniciales
  4. Eliminar posibles causas
    • Usar divide and conquer
    • Probar componentes uno por uno
    • Descartar causas obvias primero
  5. Proponer hipótesis
    • Basándose en evidencia recopilada
    • Considerar causa más probable primero
    • Tener hipótesis alternativas preparadas
  6. Probar hipótesis
    • Realizar pruebas controladas
    • Cambiar UNA variable a la vez
    • Documentar resultados de cada prueba
    • Si hipótesis falla, volver al paso 5
  7. Resolver problema y documentar
    • Implementar solución
    • Verificar que el problema está resuelto completamente
    • Monitorear para recurrencia
    • Documentar: problema, causa, solución, lecciones aprendidas
    • Actualizar knowledge base

11.2.2 Problemas de Capa Física

Los problemas en la Capa 1 (Física) son muy comunes y suelen ser la causa raíz de muchos problemas de red. La buena noticia es que generalmente son fáciles de identificar y resolver.

Síntomas Comunes de Problemas Físicos

  • Sin conectividad total: LED de link apagado
  • Conectividad intermitente: Cortes frecuentes
  • Rendimiento degradado: Velocidad muy baja
  • Errores CRC: Muchos errores de trama
  • Colisiones excesivas: En redes half-duplex
  • Latencia alta: Respuestas lentas

Causas Comunes y Soluciones

1. Cable Desconectado o Suelto

Síntomas: LED de link apagado, "cable unplugged" en Windows

Verificación:

  • Revisar ambos extremos del cable (PC y switch/router)
  • Verificar que el conector RJ-45 hace "click" al insertarse
  • Revisar LED de link en NIC y en puerto de switch

Solución: Reconectar firmemente o reemplazar cable

2. Cable Dañado o de Mala Calidad

Síntomas: Conectividad intermitente, muchos errores, velocidad baja

Causas comunes:

  • Cable pisado repetidamente (daño físico)
  • Cable muy doblado (daña hilos internos)
  • Cable cerca de fuentes de interferencia (motores, fluorescentes)
  • Cable muy largo (> 100 metros)
  • Cable de categoría incorrecta (ej: Cat3 para Gigabit)

Verificación: Usar cable tester, probar con cable conocido funcional

Solución: Reemplazar cable, usar categoría correcta, alejar de interferencias

3. Tipo de Cable Incorrecto

Problema: Usar cable directo donde se necesita cruzado (o viceversa)

Recordatorio:

  • Cable directo: PC → Switch, Router → Switch
  • Cable cruzado: PC → PC, Switch → Switch, Router → Router
  • Nota: Dispositivos modernos con Auto-MDIX detectan automáticamente

Solución: Usar tipo correcto o habilitar Auto-MDIX en switch

4. Puerto de Switch/Router Deshabilitado

Síntomas: LED apagado, show interface: "administratively down"

Causa: Puerto apagado manualmente con comando "shutdown"

Verificación:

Switch# show interface gigabitethernet 0/1
GigabitEthernet0/1 is administratively down, line protocol is down

Solución:

Switch(config)# interface gigabitethernet 0/1
Switch(config-if)# no shutdown

5. Duplex Mismatch

Síntomas: Conexión muy lenta, muchas colisiones y errores

Causa: Un lado en full-duplex, otro en half-duplex

Verificación:

Switch# show interface gigabitethernet 0/1 status
Port Status Vlan Duplex Speed Type
Gi0/1 connected 1 a-half a-100 10/100BaseTX

Solución: Configurar ambos lados en auto/auto o valores fijos iguales

Switch(config-if)# duplex auto
Switch(config-if)# speed auto

6. Interferencia Electromagnética (EMI)

Síntomas: Errores intermitentes, peor rendimiento en ciertos momentos

Causas:

  • Cables cerca de motores eléctricos
  • Fluorescentes, balastos
  • Equipos de soldadura
  • Generadores

Solución: Usar cable STP o fibra óptica, alejar cables de fuentes EMI

Checklist de Troubleshooting de Capa Física

  • ¿El cable está conectado en ambos extremos?
  • ¿El LED de link está encendido (verde)?
  • ¿El puerto está habilitado (no shutdown)?
  • ¿El cable es del tipo correcto (directo/cruzado)?
  • ¿El cable es de la categoría adecuada?
  • ¿La longitud del cable es < 100 metros?
  • ¿Duplex y speed coinciden en ambos lados?
  • ¿Hay interferencia electromagnética cerca?
  • ¿El cable está físicamente dañado?
  • ¿La NIC del dispositivo funciona correctamente?
    • # Comandos útiles para diagnosticar problemas físicos

    # Ver estado de todos los puertos
    Switch# show interface status

    # Ver detalles de interfaz específica
    Switch# show interface gigabitethernet 0/1

    # Ver errores de interfaz
    Switch# show interface gigabitethernet 0/1 | include error

    # Limpiar contadores de errores (para monitorear nuevos)
    Switch# clear counters gigabitethernet 0/1

    # Ver log de eventos del switch
    Switch# show logging

    11.2.3 Solución de Problemas de Conexión Inalámbrica

    Las redes WiFi (inalámbricas) tienen desafíos únicos debido a la naturaleza del medio de transmisión (ondas de radio). Los problemas pueden ser más complejos y variables que en redes cableadas.

    Problemas Comunes de WiFi

    1. No se Encuentra la Red WiFi (SSID Oculto)

    Síntomas: La red no aparece en la lista de redes disponibles

    Causas posibles:

    • SSID broadcasting deshabilitado (red oculta)
    • Access Point (AP) apagado o sin energía
    • Fuera del rango de cobertura
    • Problema con la antena del AP
    • Frecuencia incorrecta (2.4GHz vs 5GHz)

    Soluciones:

    • Habilitar SSID broadcast en el AP
    • Conectar manualmente ingresando el SSID exacto
    • Acercarse al AP
    • Verificar que el AP esté encendido y funcionando
    • Verificar que el dispositivo soporte la banda WiFi (5GHz requiere adaptador compatible)

    2. No se Puede Conectar a la Red (Autenticación Fallida)

    Síntomas: "No se puede conectar a esta red", "Contraseña incorrecta"

    Causas posibles:

    • Contraseña WiFi incorrecta (más común)
    • Tipo de seguridad incorrecto (WPA2 vs WPA3)
    • Filtrado MAC habilitado (MAC del dispositivo no permitida)
    • Número máximo de clientes alcanzado
    • Problema con servidor RADIUS (en redes empresariales)

    Soluciones:

    • Verificar y reingresar contraseña (cuidado con mayúsculas/minúsculas)
    • Olvidar red y reconectar desde cero
    • Verificar tipo de seguridad configurado en AP
    • Agregar MAC del dispositivo a la lista de permitidos
    • Reducir número de clientes conectados

    3. Conectado Pero Sin Internet

    Síntomas: WiFi conectado, pero navegador no carga páginas

    Causas posibles:

    • AP sin conexión a Internet (problema upstream)
    • DHCP no asigna dirección IP
    • DNS no configurado o no funciona
    • Gateway predeterminado incorrecto
    • Portal cautivo requiere autenticación (hoteles, aeropuertos)

    Diagnóstico:

    # Verificar configuración IP
    ipconfig /all # Windows

    # Probar conectividad local
    ping 192.168.1.1 # Gateway típico

    # Probar conectividad Internet por IP
    ping 8.8.8.8 # Si funciona, no es problema de conectividad

    # Probar DNS
    nslookup google.com # Si falla, es problema DNS

    Soluciones:

    • Reiniciar el router/AP
    • Configurar DNS manualmente (8.8.8.8, 1.1.1.1)
    • Renovar dirección IP: ipconfig /release y ipconfig /renew
    • Abrir navegador para autenticar en portal cautivo

    4. Señal Débil o Intermitente

    Síntomas: Conexión lenta, desconexiones frecuentes, "limited connectivity"

    Causas posibles:

    • Distancia excesiva del AP
    • Obstáculos físicos (paredes, metal, agua)
    • Interferencia de otras redes WiFi
    • Interferencia de dispositivos (microondas, Bluetooth, baby monitors)
    • Canal WiFi congestionado
    • Antenas del AP mal orientadas

    Soluciones:

    • Acercarse al AP o instalar AP adicionales (extender cobertura)
    • Cambiar ubicación del AP a posición más central
    • Cambiar canal WiFi (usar analizador de WiFi para encontrar canal menos congestionado)
    • Usar banda de 5GHz si hay mucha interferencia en 2.4GHz
    • Actualizar firmware del AP
    • Instalar repetidores o mesh WiFi

    5. Velocidad Lenta en WiFi

    Síntomas: Internet funciona pero muy lento comparado con cableado

    Causas posibles:

    • Señal débil (ver problema anterior)
    • Muchos dispositivos conectados al mismo AP
    • AP usando estándar antiguo (802.11b/g en lugar de n/ac/ax)
    • Interferencia
    • Ancho de banda limitado por el ISP
    • QoS limitando ciertos tipos de tráfico

    Diagnóstico:

    • Probar velocidad con test (speedtest.net) en WiFi y cableado
    • Si cableado es rápido y WiFi lento → problema de WiFi
    • Si ambos lentos → problema upstream (ISP)

    Soluciones:

    • Reducir número de clientes simultáneos
    • Actualizar a AP más moderno (WiFi 6/6E)
    • Usar banda de 5GHz para dispositivos compatibles
    • Configurar QoS para priorizar aplicaciones críticas

    Canales WiFi e Interferencia

    2.4 GHz - Canales 1-11 (en América)

    • Solo 3 canales NO se superponen: 1, 6, 11
    • Si usas canal 3, interferirás con 1, 6 y otros
    • Recomendación: Usar SOLO canales 1, 6 u 11
    • Usar analizador WiFi (WiFi Analyzer en Android) para ver qué canales están congestionados

    5 GHz - Muchos canales no superpuestos

    • Ventajas: Menos interferencia, más canales disponibles, mayor velocidad
    • Desventajas: Menor alcance, no penetra paredes tan bien como 2.4GHz
    • Mejor para: Dispositivos cercanos que necesitan alta velocidad

    Checklist de Troubleshooting WiFi

  • ¿El WiFi está habilitado en el dispositivo?
  • ¿El SSID es correcto?
  • ¿La contraseña es correcta?
  • ¿El dispositivo está dentro del rango del AP?
  • ¿Hay obstáculos físicos bloqueando la señal?
  • ¿El canal WiFi está congestionado?
  • ¿Hay interferencia de otros dispositivos?
  • ¿El AP tiene la última versión de firmware?
  • ¿DHCP está asignando IP correctamente?
  • ¿El AP tiene conexión a Internet?

    • 11.2.4 Problemas Comunes de Conectividad a Internet

    Los problemas de conectividad a Internet afectan a toda la red y requieren un enfoque sistemático para identificar si el problema está en la red local o con el ISP.

    1. No Hay Conexión a Internet (Toda la Red Afectada)

    Síntomas: Nadie puede acceder a Internet, solo funciona red local

    Diagnóstico paso a paso:

    1. Verificar luces del módem/router:
      • LED de Power: Debe estar verde/azul (encendido OK)
      • LED de Internet/WAN: Debe estar verde (conectado)
      • Si está rojo/ámbar/parpadeando: Problema de conexión ISP
    2. Probar desde el router:
      Router# ping 8.8.8.8 # Google DNS
      Router# ping 1.1.1.1 # Cloudflare DNS
      • Si router puede hacer ping → problema en la red interna
      • Si router NO puede hacer ping → problema con ISP o configuración WAN
    3. Verificar configuración WAN del router:
      • ¿Tiene dirección IP pública asignada?
      • ¿Gateway está configurado?
      • ¿DNS funcionando?

    Soluciones comunes:

    • Reiniciar módem y router (en este orden):
      1. Apagar router
      2. Apagar módem
      3. Esperar 30 segundos
      4. Encender módem, esperar que todas las luces estabilicen
      5. Encender router, esperar que arranque
    • Verificar cables (módem-router, módem-pared)
    • Contactar al ISP si problema persiste

    2. Internet Lento (Toda la Red)

    Síntomas: Internet funciona pero es muy lento para todos

    Diagnóstico:

    • Test de velocidad: Usar speedtest.net
      • Probar con dispositivo cableado directo al router
      • Comparar con velocidad contratada con ISP
    • Revisar uso de ancho de banda:
      • ¿Alguien descargando archivos grandes?
      • ¿Streaming de video 4K en múltiples dispositivos?
      • ¿Backups automáticos a la nube?
      • ¿Malware consumiendo ancho de banda?

    Soluciones:

    • Limitar aplicaciones que consumen mucho ancho de banda
    • Configurar QoS en el router para priorizar tráfico
    • Actualizar plan de Internet con ISP
    • Escanear dispositivos en busca de malware

    3. Algunos Sitios Web No Cargan (DNS)

    Síntomas: ping a 8.8.8.8 funciona, pero navegador no carga sitios

    Causa probable: Problema de DNS

    Verificación:

    # Probar DNS
    nslookup google.com

    # Ver servidores DNS configurados
    ipconfig /all # Windows
    cat /etc/resolv.conf # Linux

    Soluciones:

    • Cambiar DNS a servidores públicos:
      • Google: 8.8.8.8 y 8.8.4.4
      • Cloudflare: 1.1.1.1 y 1.0.0.1
    • Limpiar caché DNS: ipconfig /flushdns
    • Reiniciar el router (puede tener caché DNS corrupta)

    4. Conexión Intermitente (Cortes Frecuentes)

    Síntomas: Internet funciona pero se corta cada cierto tiempo

    Causas posibles:

    • Problema con el ISP (línea inestable)
    • Cable del módem dañado o mal conectado
    • Módem/router sobrecalentado
    • Firmware desactualizado
    • Configuración de ahorro de energía en adaptador de red

    Diagnóstico:

    • Monitorear con ping continuo: ping -t 8.8.8.8
    • Revisar logs del router para eventos de desconexión
    • Verificar temperatura del módem/router (tocar, no debe estar muy caliente)

    Soluciones:

    • Mejorar ventilación del módem/router
    • Actualizar firmware
    • Reemplazar cables sospechosos
    • Contactar ISP para verificar calidad de línea
    • Deshabilitar ahorro de energía en adaptador de red

    Metodología de Diagnóstico de Internet

    Estrategia de Ping Progresivo

    1. Ping al gateway local: ping 192.168.1.1
      • Si falla → problema en red local (cable, WiFi, config IP)
      • Si funciona → continuar
    2. Ping a IP pública (DNS de Google): ping 8.8.8.8
      • Si falla → problema con ISP o router WAN
      • Si funciona → problema de DNS
    3. Ping a nombre de dominio: ping google.com
      • Si falla → problema de DNS
      • Si funciona → problema en el navegador/aplicación específica

    11.2.5 Asistencia al Cliente

    Proporcionar soporte técnico efectivo requiere no solo conocimientos técnicos, sino también habilidades de comunicación y gestión de expectativas.

    Mejores Prácticas de Soporte Técnico

    1. Comunicación Efectiva

    • Escuchar activamente: Dejar que el usuario describa el problema completamente sin interrumpir
    • Hacer preguntas abiertas: "¿Qué estaba haciendo cuando ocurrió?" vs "¿Reinició la computadora?"
    • Evitar jerga técnica: Adaptar el lenguaje al nivel del usuario
    • Confirmar comprensión: "Entonces, me dice que no puede acceder al correo desde esta mañana, ¿correcto?"
    • Ser paciente: Muchos usuarios no son técnicos

    2. Gestión de Tickets/Casos

    • Documentar todo: Síntomas, pruebas realizadas, soluciones intentadas
    • Asignar prioridad:
      • Crítico: Toda la red caída, sistemas de producción
      • Alto: Departamento afectado, pérdida de productividad
      • Medio: Usuario individual, workarounds disponibles
      • Bajo: Solicitudes, mejoras, problemas estéticos
    • Mantener al usuario informado: Actualizaciones cada cierto tiempo
    • Seguimiento: Confirmar que la solución funcionó después de cerrar el ticket

    3. Recopilación de Información

    Preguntas clave para hacer al usuario:

    • ¿Cuál es el problema exacto? (síntomas específicos)
    • ¿Cuándo comenzó?
    • ¿Funcionó alguna vez correctamente?
    • ¿Qué cambió recientemente? (actualizaciones, nuevo software, movimiento de equipo)
    • ¿A cuántas personas afecta? (uno, varios, todos)
    • ¿Puede reproducir el problema?
    • ¿Cuál es el impacto en el negocio?
    • ¿Hay algún mensaje de error? (pedirlo textual o captura de pantalla)

    4. Resolución Remota

    • Herramientas: TeamViewer, AnyDesk, Windows Remote Desktop, SSH
    • Ventajas: Más rápido, no requiere visita presencial, puedes ver exactamente el problema
    • Consideraciones:
      • Pedir permiso al usuario antes de tomar control
      • Explicar lo que estás haciendo
      • Respetar la privacidad (cerrar documentos personales visibles)
      • Documentar todo lo que haces

    5. Escalamiento de Problemas

    Cuándo escalar a nivel superior:

    • El problema está fuera de tu área de expertise
    • Has agotado tus opciones de troubleshooting
    • El problema requiere acceso/permisos que no tienes
    • El impacto es crítico y necesitas ayuda adicional
    • El SLA (Service Level Agreement) está en riesgo

    Cómo escalar efectivamente:

    • Proporcionar toda la información recopilada
    • Detallar pasos de troubleshooting ya realizados
    • Explicar por qué estás escalando
    • Permanecer disponible por si tienen preguntas
    Ejemplo de Interacción de Soporte Efectiva

    Usuario: "¡El internet no funciona!"

    Técnico MAL: "¿Reiniciaste el router?"
    (Demasiado directo, no recabó información)

    Técnico BIEN:
    "Entiendo, debe ser frustrante. Déjame hacerte algunas preguntas para ayudarte mejor:
    • ¿Desde cuándo tienes este problema?
    • ¿Afecta solo a tu computadora o a más dispositivos?
    • ¿Puedes ver el icono de WiFi en tu pantalla?
    • ¿Aparece algún mensaje de error específico?"

    Usuario: "Desde esta mañana, solo mi laptop, el WiFi aparece conectado pero no puedo abrir ninguna página web."

    Técnico: "Perfecto, vamos a revisar esto paso a paso. Primero, vamos a verificar si es un problema de DNS..."
    Reglas de Oro del Soporte Técnico:

    1. Nunca culpar al usuario - "Probablemente clickeaste algo malo" ✗
    2. No asumir conocimientos técnicos - Explicar en términos simples
    3. Ser empático - El usuario está frustrado, comprender su situación
    4. Documentar TODO - Hoy confías en tu memoria, mañana no recordarás
    5. Seguir procedimientos - Por algo existen los procesos establecidos
    6. Aprender de cada caso - Cada problema es una oportunidad de aprender
    7. Mantener la calma - Incluso si el usuario está molesto
    8. No prometer lo que no puedes cumplir - Es mejor ser honesto sobre tiempos

    Checklist de Cierre de Ticket

  • ¿El problema está resuelto completamente?
  • ¿El usuario confirmó que funciona?
  • ¿Documentaste la causa raíz?
  • ¿Documentaste la solución aplicada?
  • ¿Actualizaste la base de conocimiento si es necesario?
  • ¿Identificaste formas de prevenir recurrencia?
  • ¿Explicaste al usuario qué causó el problema?
  • ¿Proporcionaste tips para evitar problemas futuros?

    • Puntos Clave de la Clase 11

    • Switches operan en Capa 2 (MAC), routers en Capa 3 (IP) - funciones diferentes
    • Store-and-forward es el método de conmutación más común y confiable
    • Duplex mismatch es un problema común que causa conexiones muy lentas
    • El proceso de arranque incluye: POST, Boot Loader, carga de IOS, configuración
    • Running-config está en RAM (volátil), startup-config en NVRAM (persistente)
    • Usar metodología sistemática de troubleshooting (7 pasos) para eficiencia
    • Problemas físicos son muy comunes: verificar cables, LEDs, puertos primero
    • WiFi tiene desafíos únicos: señal, interferencia, canales, distancia
    • Usar ping progresivo para diagnosticar: gateway local → IP pública → nombre dominio
    • Problemas de DNS se manifiestan como "Internet no funciona" pero ping a IPs funciona
    • Documentar TODO: síntomas, pruebas, soluciones - conocimiento organizacional
    • Comunicación efectiva con usuarios es tan importante como conocimiento técnico
