2.1 El Protocolo de Internet

2.1.0 Introducción

El Protocolo de Internet (IP) es el protocolo fundamental de la capa de red en los modelos OSI y TCP/IP. Es responsable de la entrega de paquetes de datos desde el host origen hasta el host destino a través de redes interconectadas. IP es un protocolo sin conexión (connectionless), lo que significa que no establece una conexión dedicada antes de enviar datos, sino que cada paquete se trata de forma independiente.

El protocolo IP opera en la Capa 3 (Red) del modelo OSI y en la Capa de Internet del modelo TCP/IP. Su función principal es el direccionamiento lógico y el enrutamiento de paquetes a través de diferentes redes.

Nota: Aunque IP es el protocolo de capa de red más importante, no es el único. Otros protocolos como ICMP (Internet Control Message Protocol), IGMP (Internet Group Management Protocol) y ARP (Address Resolution Protocol) también operan en esta capa y complementan las funciones de IP.

El protocolo IP ha tenido dos versiones principales en uso:

  • IPv4 (Internet Protocol version 4): Versión 4 de IP, actualmente la más utilizada en Internet y redes corporativas
  • IPv6 (Internet Protocol version 6): Versión 6 de IP, diseñada para superar las limitaciones de IPv4, especialmente el agotamiento de direcciones

2.1.1 Propósito de una Dirección IPv4

Una dirección IPv4 es un identificador lógico único de 32 bits que se asigna a cada interfaz de red de un dispositivo en una red TCP/IP. Las direcciones IPv4 cumplen varios propósitos fundamentales:

Cada dispositivo (laptop, celular, tablet) necesita su propia dirección IPv4 para identificarse en la red

Funciones Principales:

  • Identificación única de dispositivos: Cada dispositivo conectado a una red IP necesita una dirección única para ser identificado. Sin esta identificación, sería imposible distinguir entre diferentes dispositivos en la red.
  • Enrutamiento de paquetes: Las direcciones IP permiten que los routers tomen decisiones sobre cómo reenviar paquetes a través de múltiples redes intermedias hasta llegar al destino correcto. Los routers examinan la dirección IP de destino para determinar el mejor camino.
  • Comunicación bidireccional: Permite que dos dispositivos se comuniquen entre sí, independientemente de su ubicación física en la red o en Internet. La dirección IP de origen permite al destinatario responder.
  • Organización jerárquica: Las direcciones IP tienen una estructura jerárquica que facilita la organización lógica de la red en subredes, mejorando la administración y el rendimiento.

Componentes de una Dirección IPv4:

Cada dirección IPv4 consta de dos componentes lógicos esenciales:

  • Porción de Red (Network Portion): Los bits que identifican la red específica a la que pertenece el dispositivo. Todos los dispositivos en la misma red comparten estos bits.
  • Porción de Host (Host Portion): Los bits que identifican el dispositivo específico dentro de esa red. Cada dispositivo en la misma red debe tener una porción de host única.

La división entre las porciones de red y host se determina mediante la máscara de subred, que estudiaremos más adelante en la sección 3.2.3.

2.1.2 La Estructura de la Dirección IPv4

Una dirección IPv4 está compuesta por 32 bits, divididos en 4 secciones de 8 bits cada una. Estas secciones se llaman octetos (porque contienen 8 bits). La representación estándar de una dirección IPv4 se conoce como notación decimal con puntos (dotted-decimal notation).

Características Estructurales:

  • 32 bits totales: Divididos en 4 octetos de 8 bits cada uno
  • Formato decimal: Cada octeto se expresa como un número decimal entre 0 y 255
  • Separación por puntos: Los octetos se separan con puntos (.) para facilitar la lectura
  • Rango de valores por octeto: 0 a 255 (porque 2⁸ = 256 valores posibles: 0-255)
Ejemplo de dirección IPv4:

Notación decimal con puntos: 192.168.1.100

Desglose por octetos:
• Primer octeto: 192
• Segundo octeto: 168
• Tercer octeto: 1
• Cuarto octeto: 100

Representación binaria completa:
11000000.10101000.00000001.01100100

Conversión Binario-Decimal:

Para comprender completamente las direcciones IPv4, es fundamental saber convertir entre notación binaria y decimal. Cada bit en un octeto tiene un valor posicional basado en potencias de 2.

Posición del bit 8 7 6 5 4 3 2 1
Potencia binaria 2⁷ 2⁶ 2⁵ 2⁴ 2³ 2² 2¹ 2⁰
Valor decimal 128 64 32 16 8 4 2 1
Ejemplo de conversión detallado:

Dirección IP: 192.168.1.10

Primer octeto (192):
Binario: 11000000
Cálculo: (1×128) + (1×64) + (0×32) + (0×16) + (0×8) + (0×4) + (0×2) + (0×1)
Resultado: 128 + 64 = 192 ✓

Segundo octeto (168):
Binario: 10101000
Cálculo: (1×128) + (0×64) + (1×32) + (0×16) + (1×8) + (0×4) + (0×2) + (0×1)
Resultado: 128 + 32 + 8 = 168 ✓

Tercer octeto (1):
Binario: 00000001
Cálculo: (0×128) + (0×64) + (0×32) + (0×16) + (0×8) + (0×4) + (0×2) + (1×1)
Resultado: 1 ✓

Cuarto octeto (10):
Binario: 00001010
Cálculo: (0×128) + (0×64) + (0×32) + (0×16) + (0×8) + (1×4) + (0×2) + (1×2)
Resultado: 8 + 2 = 10 ✓

Rango Total de Direcciones IPv4:

  • Dirección más baja: 0.0.0.0 (00000000.00000000.00000000.00000000 en binario)
  • Dirección más alta: 255.255.255.255 (11111111.11111111.11111111.11111111 en binario)
  • Total de direcciones posibles: 2³² = 4,294,967,296 direcciones (~4.3 mil millones)

2.2 IPv4 y Segmentación de Redes

2.2.0 Introducción

La segmentación de redes es el proceso estratégico de dividir una red grande en subredes (subnets) más pequeñas y manejables. Esta práctica es fundamental en el diseño de redes modernas porque mejora el rendimiento, la seguridad, y facilita la administración. Para comprender completamente la segmentación, primero debemos entender los diferentes tipos de comunicación que existen en IPv4 y cómo las direcciones se clasifican.

2.2.1 Unidifusión, Difusión y Multidifusión de IPv4

En las redes IPv4 existen tres formas básicas de comunicación entre dispositivos. Cada tipo tiene un propósito específico y características únicas:

1. Unidifusión (Unicast)

La comunicación de unidifusión es de tipo uno-a-uno. Un único host origen envía datos a un único host destino específico identificado por su dirección IP individual.

Características principales de Unicast:

  • Un dispositivo origen envía datos a un destino específico identificado por su dirección IP única
  • Es la forma de comunicación más común en redes TCP/IP
  • El paquete viaja solo al destino especificado, otros dispositivos lo ignoran
  • Eficiente para comunicaciones punto a punto
  • Ejemplos de uso: navegación web, correo electrónico, transferencia de archivos FTP, sesiones SSH
  • Rango de direcciones unicast: 1.0.0.0 a 223.255.255.255 (excluyendo rangos especiales)
Ejemplo práctico de comunicación Unicast:

Escenario: Un usuario en la PC 172.16.4.1 quiere enviar un archivo al servidor 172.16.4.253

Proceso:
1. La PC 172.16.4.1 crea un paquete con:
   • IP origen: 172.16.4.1
   • IP destino: 172.16.4.253
2. El paquete viaja por la red hasta el servidor 172.16.4.253
3. Solo el servidor 172.16.4.253 recibe y procesa el archivo
4. Los demás dispositivos (172.16.4.2, 172.16.4.3, etc.) ignoran este tráfico

Resultado: Comunicación privada y eficiente entre dos dispositivos específicos

2. Difusión (Broadcast)

La comunicación de difusión es de tipo uno-a-todos. Un host envía datos simultáneamente a todos los hosts que se encuentran en la misma red o subred local.

Características principales de Broadcast:

  • Un origen envía datos simultáneamente a todos los hosts del segmento de red
  • La dirección de difusión siempre es la última dirección de la subred
  • En formato binario, todos los bits de host están en 1
  • No atraviesa routers por defecto (dominio de broadcast limitado por routers)
  • Puede generar tráfico innecesario si se usa excesivamente
  • Útil para servicios de descubrimiento y anuncios
  • Ejemplos de uso: DHCP discovery, ARP requests, anuncios de servicios

Tipos de Broadcast:

  • Broadcast dirigido (Directed Broadcast): Se envía a todos los hosts de una red específica. Ejemplo: 192.168.1.255 para la red 192.168.1.0/24
  • Broadcast limitado (Limited Broadcast): Se envía a todos los hosts de la red local usando la dirección especial 255.255.255.255. No atraviesa routers bajo ninguna circunstancia.
Ejemplo práctico de comunicación Broadcast:

Escenario: Un PC en la red 172.16.4.0/24 necesita encontrar la dirección MAC de otro dispositivo

Proceso ARP (Address Resolution Protocol):
1. PC origen envía ARP Request por broadcast a 172.16.4.255
2. Mensaje: "¿Quién tiene la IP 172.16.4.50? Por favor responde a 172.16.4.1"
3. El mensaje llega a TODOS los dispositivos de la red:
   • 172.16.4.1, 172.16.4.2, 172.16.4.3, ..., 172.16.4.254
4. Solo el dispositivo con IP 172.16.4.50 responde con un unicast
5. Respuesta: "Yo tengo 172.16.4.50, mi MAC es AA:BB:CC:DD:EE:FF"

Resultado: Todos recibieron el mensaje, pero solo uno respondió
Comando Windows - Enviar ping a dirección de broadcast limitado: ping 255.255.255.255

3. Multidifusión (Multicast)

La comunicación de multidifusión es de tipo uno-a-múltiples. Un host envía datos a un grupo específico de hosts que han expresado interés en recibir ese tráfico uniéndose a un grupo multicast.

Características principales de Multicast:

  • Un origen envía datos a un grupo selecto de hosts suscritos al grupo multicast
  • Solo los dispositivos que se unieron al grupo multicast reciben los datos
  • Rango de direcciones multicast: 224.0.0.0 a 239.255.255.255 (Clase D)
  • Más eficiente que broadcast cuando solo algunos hosts necesitan los datos
  • Reduce significativamente el ancho de banda comparado con múltiples unicast
  • Requiere soporte de protocolos como IGMP (Internet Group Management Protocol)
  • Ejemplos de uso: streaming de video en vivo, videoconferencias, distribución de software, cotizaciones bursátiles en tiempo real, juegos en línea

Rangos importantes de direcciones Multicast:

  • 224.0.0.0 - 224.0.0.255: Multicast de enlace local, reservado para protocolos de enrutamiento. No sale del segmento de red local.
  • 224.0.1.0 - 238.255.255.255: Multicast enrutable globalmente, puede atravesar Internet.
  • 239.0.0.0 - 239.255.255.255: Multicast de ámbito limitado, para uso en organizaciones privadas (similar a IPs privadas).
Ejemplo práctico de comunicación Multicast:

Escenario: Una empresa transmite una videoconferencia corporativa en vivo

Configuración:
• Dirección multicast asignada: 239.192.1.100
• Servidor de video: 192.168.1.50
• Red: 172.16.4.0/24 con 200 dispositivos

Proceso:
1. Empleados interesados unen sus PCs al grupo multicast 239.192.1.100
   • PC 172.16.4.10 se une al grupo
   • PC 172.16.4.25 se une al grupo
   • PC 172.16.4.88 se une al grupo
2. El servidor envía el stream de video a 239.192.1.100
3. Solo las 3 PCs que se unieron reciben el video
4. Los otros 197 dispositivos NO reciben el tráfico

Beneficio: En lugar de enviar 3 copias separadas (unicast) o 200 copias (broadcast), se envía una sola copia que solo llega a los interesados. Ahorro masivo de ancho de banda.

2.2.2 Tipos de Direcciones IPv4

Las direcciones IPv4 se clasifican en diferentes categorías según su función, rango y uso previsto. Esta clasificación es fundamental para entender cómo se organizan y administran las redes a nivel mundial.

Sistema de Clases (Classful Addressing)

Originalmente, las direcciones IPv4 se dividieron en cinco clases (A, B, C, D, E) basadas en el valor del primer octeto. Este sistema, conocido como direccionamiento classful, fue el método de asignación de direcciones desde 1981 hasta 1993.

Clase Primer Octeto Primer bit(s) Bits Red/Host Máscara Defecto Redes Hosts/Red Uso Principal
Clase A 1 - 126 0 8 red / 24 host 255.0.0.0 (/8) 126 16,777,214 Redes muy grandes (multinacionales, ISPs)
Clase B 128 - 191 10 16 red / 16 host 255.255.0.0 (/16) 16,384 65,534 Redes medianas (universidades, empresas grandes)
Clase C 192 - 223 110 24 red / 8 host 255.255.255.0 (/24) 2,097,152 254 Redes pequeñas (oficinas, hogares)
Clase D 224 - 239 1110 - - - - Multicast (grupos)
Clase E 240 - 255 1111 - - - - Experimental / Investigación
Ejemplos de cada clase:

Clase A: 10.0.0.1 (red privada), 50.100.200.1 (pública)
• Primer octeto entre 1-126
• Ideal para organizaciones con millones de dispositivos

Clase B: 172.16.0.1 (privada), 150.100.50.1 (pública)
• Primer octeto entre 128-191
• Ideal para universidades y empresas medianas

Clase C: 192.168.1.1 (privada), 200.50.100.1 (pública)
• Primer octeto entre 192-223
• Ideal para oficinas pequeñas y hogares

Clase D: 224.0.0.1 (multicast)
• Primer octeto entre 224-239
• No se asigna a dispositivos individuales

Clase E: 240.0.0.1 (experimental)
• Primer octeto entre 240-255
• Reservada para investigación, no usable en producción
Nota Histórica: El sistema de clases (classful) fue reemplazado en 1993 por CIDR (Classless Inter-Domain Routing), que permite máscaras de subred de cualquier longitud. Sin embargo, las clases siguen siendo útiles para entender rangos de direcciones y diseño de redes.

Direcciones Privadas vs. Públicas

Direcciones IP Privadas (RFC 1918):

Son direcciones reservadas específicamente para uso en redes internas/privadas. Estas direcciones NO son enrutables en Internet público, lo que significa que los routers de Internet están configurados para descartar paquetes con estas direcciones como origen o destino. Pueden ser reutilizadas en diferentes organizaciones sin causar conflictos.

Clase Rango de Direcciones Privadas Notación CIDR Número de Direcciones Uso Típico
Clase A 10.0.0.0 - 10.255.255.255 10.0.0.0/8 16,777,216 Grandes corporaciones, datacenters
Clase B 172.16.0.0 - 172.31.255.255 172.16.0.0/12 1,048,576 Empresas medianas, campus universitarios
Clase C 192.168.0.0 - 192.168.255.255 192.168.0.0/16 65,536 Hogares, oficinas pequeñas (SOHO)

Direcciones IP Públicas:

Son direcciones únicas a nivel global, asignadas por autoridades de numeración (IANA y RIRs regionales) y completamente enrutables en Internet. Cada dirección pública solo puede ser usada por una organización a la vez en todo el mundo.

  • Asignación jerárquica: IANA → RIRs (ARIN, RIPE, APNIC, LACNIC, AFRINIC) → ISPs → Usuarios finales
  • Costo: Las organizaciones pagan por bloques de direcciones públicas
  • Responsabilidad: Deben ser documentadas y justificadas ante los registros regionales
Ejemplo de arquitectura típica con IPs privadas y públicas:

Red Interna de una Empresa (IPs Privadas):
• Computadoras de oficina: 192.168.1.10, 192.168.1.11, 192.168.1.12
• Impresoras de red: 192.168.1.50, 192.168.1.51
• Servidor de archivos: 192.168.1.100
• Servidor web interno: 192.168.1.101
• Total de dispositivos: 100+

Conexión a Internet (IP Pública):
• Router/Firewall externo: 200.45.67.89 (única IP pública)
• Esta IP es visible en Internet

Funcionamiento con NAT:
1. Dispositivo interno 192.168.1.10 quiere acceder a google.com
2. El router hace NAT (Network Address Translation)
3. Convierte la IP origen de 192.168.1.10 a 200.45.67.89
4. Google ve la solicitud desde 200.45.67.89
5. La respuesta vuelve a 200.45.67.89
6. El router la reenvía internamente a 192.168.1.10

Ventaja: 100+ dispositivos comparten 1 sola IP pública

Direcciones Especiales IPv4

Existen varios rangos y direcciones con propósitos especiales reservados por la IANA:

Dirección / Rango Nombre Propósito RFC

127.0.0.0/8 Loopback Tráfico de prueba interno del dispositivo. 127.0.0.1 es "localhost" RFC 1122

Comando Windows - Probar conectividad con localhost (nombre): ping localhost

Caso de APIPA (169.254.x.x):

Escenario: Una computadora está configurada para DHCP pero no puede contactar al servidor DHCP

Proceso:
1. La PC envía DHCP DISCOVER (broadcast)
2. No recibe respuesta (DHCP OFFER)
3. Después de varios intentos, activa APIPA
4. Se asigna automáticamente una IP en el rango 169.254.1.0 - 169.254.254.255
5. Ejemplo: 169.254.100.50 con máscara 255.255.0.0

Limitaciones:
• Solo puede comunicarse con otros dispositivos APIPA en el mismo segmento
• No tiene gateway, por lo tanto no puede acceder a Internet
• No tiene servidores DNS configurados

Solución: Verificar conectividad con el servidor DHCP o configurar IP estática

2.2.3 Segmentación de la Red (Subnetting)

La segmentación de red, también conocida como subnetting o subdivisión de redes, es el proceso de dividir una red grande en subredes (subnets) más pequeñas y manejables. Este proceso se logra mediante el uso de máscaras de subred que determinan qué parte de una dirección IP identifica la red y qué parte identifica el host.

¿Qué es una Máscara de Subred?

Una máscara de subred (subnet mask) es un número de 32 bits que acompaña siempre a una dirección IP. Su función es dividir la dirección IP en dos componentes lógicos:

  • Parte de Red (Network Portion): Los bits en 1 en la máscara identifican qué parte de la IP corresponde a la red o subred
  • Parte de Host (Host Portion): Los bits en 0 en la máscara identifican qué parte de la IP corresponde al dispositivo específico

Reglas importantes de las máscaras de subred:

  • Siempre tienen 32 bits (como las direcciones IP)
  • Los bits de red (1s) siempre están a la izquierda, contiguos
  • Los bits de host (0s) siempre están a la derecha, contiguos
  • No puede haber bits de host (0s) entre bits de red (1s)
Ejemplo detallado de máscara de subred:

Configuración:
Dirección IP: 192.168.1.100
Máscara de subred: 255.255.255.0

Representación binaria:
IP: 11000000.10101000.00000001.01100100
Máscara: 11111111.11111111.11111111.00000000
         |←──── 24 bits de red ────→||← 8 bits host →|

Análisis:
• Porción de Red: Primeros 24 bits (3 octetos) = 192.168.1
  → Todos los dispositivos en esta red comparten estos bits
• Porción de Host: Últimos 8 bits (1 octeto) = 100
  → Identifica este dispositivo específico

Cálculos de la subred:
• Dirección de red: 192.168.1.0 (primer octeto de host = 0)
• Dirección de broadcast: 192.168.1.255 (todos los bits de host = 1)
• Primer host válido: 192.168.1.1
• Último host válido: 192.168.1.254
• Total de hosts utilizables: 2⁸ - 2 = 256 - 2 = 254 hosts
  (Se restan 2: dirección de red y broadcast)

Notación CIDR (Classless Inter-Domain Routing)

CIDR es una notación compacta y moderna para expresar la máscara de subred. Usa una barra diagonal (/) seguida del número de bits de red (bits en 1 en la máscara).

Formato: direccion_ip/bits_de_red

CIDR Máscara Decimal Máscara Binaria (último octeto) Hosts por Subred Uso Típico
/8 255.0.0.0 00000000 16,777,214 Clase A estándar
/16 255.255.0.0 00000000 65,534 Clase B estándar
/24 255.255.255.0 00000000 254 Clase C estándar, red típica
/25 255.255.255.128 10000000 126 2 subredes de 126 hosts
/26 255.255.255.192 11000000 62 4 subredes de 62 hosts
/27 255.255.255.224 11100000 30 8 subredes de 30 hosts
/28 255.255.255.240 11110000 14 16 subredes de 14 hosts
/29 255.255.255.248 11111000 6 32 subredes de 6 hosts
/30 255.255.255.252 11111100 2 Enlaces punto a punto
/32 255.255.255.255 11111111 1 Host específico
Ejemplos de notación CIDR:

• 192.168.1.0/24 = Red con máscara 255.255.255.0
  → 24 bits de red, 8 bits de host, 254 hosts utilizables

• 10.0.0.0/8 = Red con máscara 255.0.0.0
  → 8 bits de red, 24 bits de host, 16,777,214 hosts utilizables

• 172.16.0.0/16 = Red con máscara 255.255.0.0
  → 16 bits de red, 16 bits de host, 65,534 hosts utilizables

• 192.168.1.128/25 = Subred con máscara 255.255.255.128
  → 25 bits de red, 7 bits de host, 126 hosts utilizables

• 10.1.1.1/32 = Host específico (ruta de host)
  → 32 bits de red, 0 bits de host, representa un dispositivo único

Ventajas de la Segmentación de Redes

La segmentación de redes proporciona múltiples beneficios operacionales y de seguridad:

  • Mejora el rendimiento de la red:
    • Reduce el dominio de broadcast (menos dispositivos reciben broadcasts)
    • Disminuye la congestión de tráfico
    • Mejora los tiempos de respuesta
  • Aumenta la seguridad:
    • Facilita el aislamiento de segmentos críticos (ej: servidores, contabilidad)
    • Permite implementar políticas de seguridad específicas por segmento
    • Contiene problemas de seguridad en subredes específicas
    • Facilita la implementación de VLANs
  • Mejor organización lógica:
    • Agrupa dispositivos por departamento, función o ubicación
    • Ejemplo: Subred para Contabilidad, otra para Ventas, otra para IT
    • Facilita la gestión y el troubleshooting
  • Uso eficiente de direcciones IP:
    • Permite asignar solo las direcciones necesarias por segmento
    • Optimiza el espacio de direccionamiento
    • Reduce el desperdicio de IPs
  • Control de tráfico y QoS:
    • Permite implementar Quality of Service por subred
    • Facilita el control de ancho de banda
    • Mejora la priorización de tráfico crítico
Comando Windows - Ver configuración de red con máscara: ipconfig | findstr /i "IPv4 Mask"

Proceso de Cálculo de Subredes

Para diseñar y calcular subredes correctamente, debes seguir un proceso sistemático:

Fórmulas fundamentales:

  • Número de subredes: 2ⁿ (donde n = bits "prestados" de la porción de host)
  • Número de hosts por subred: 2ʰ - 2 (donde h = bits restantes de host)
  • Incremento de subred: 256 - valor del último octeto de la máscara

Pasos para calcular subredes:

  1. Determinar cuántas subredes necesitas
  2. Calcular los bits necesarios para esas subredes: 2ⁿ ≥ subredes_necesarias
  3. Calcular la nueva máscara de subred
  4. Determinar el incremento de subred
  5. Listar las subredes resultantes con sus rangos
Ejemplo Práctico Completo de Subnetting:

Escenario:
• Red original: 192.168.1.0/24
• Requisito: Dividir en 4 subredes
• Objetivo: Separar departamentos (IT, Ventas, Contabilidad, Gerencia)

Paso 1: Determinar bits necesarios
• Necesitamos 4 subredes
• 2¹ = 2 subredes (insuficiente)
• 2² = 4 subredes (exacto) ✓
• Necesitamos prestar 2 bits de la porción de host

Paso 2: Calcular nueva máscara
• Máscara original: /24 (255.255.255.0)
• Bits prestados: 2
• Nueva máscara: /26 (255.255.255.192)
• Binario del último octeto: 11000000 = 128 + 64 = 192

Paso 3: Calcular hosts por subred
• Bits de host originales: 8
• Bits prestados para subredes: 2
• Bits de host restantes: 8 - 2 = 6 bits
• Hosts utilizables por subred: 2⁶ - 2 = 64 - 2 = 62 hosts

Paso 4: Calcular incremento de subred
• Incremento = 256 - 192 = 64
• Las subredes van de 64 en 64

Paso 5: Listar las subredes

Subred 1 (IT):
• Dirección de red: 192.168.1.0/26
• Primera IP utilizable: 192.168.1.1
• Última IP utilizable: 192.168.1.62
• Dirección de broadcast: 192.168.1.63
• Total hosts: 62

Subred 2 (Ventas):
• Dirección de red: 192.168.1.64/26
• Primera IP utilizable: 192.168.1.65
• Última IP utilizable: 192.168.1.126
• Dirección de broadcast: 192.168.1.127
• Total hosts: 62

Subred 3 (Contabilidad):
• Dirección de red: 192.168.1.128/26
• Primera IP utilizable: 192.168.1.129
• Última IP utilizable: 192.168.1.190
• Dirección de broadcast: 192.168.1.191
• Total hosts: 62

Subred 4 (Gerencia):
• Dirección de red: 192.168.1.192/26
• Primera IP utilizable: 192.168.1.193
• Última IP utilizable: 192.168.1.254
• Dirección de broadcast: 192.168.1.255
• Total hosts: 62

Resultado: 4 subredes independientes, cada una con 62 hosts utilizables
Consejo Práctico: La máscara /30 (255.255.255.252) es muy común para enlaces punto a punto entre routers, ya que proporciona exactamente 2 direcciones de host utilizables, justo lo necesario para conectar dos dispositivos.

Ejemplo de enlace punto a punto:
• Red: 10.1.1.0/30
• Router 1: 10.1.1.1
• Router 2: 10.1.1.2
• Broadcast: 10.1.1.3
Recuerda: Siempre se pierden 2 direcciones por subred:
1. Dirección de red: Primera dirección (todos los bits de host en 0) - identifica la subred
2. Dirección de broadcast: Última dirección (todos los bits de host en 1) - para enviar a todos los hosts de la subred
