Clase 5 — Gateways, NAT, ARP y Enrutamiento

💻 Cisco Packet Tracer
Objetivo: Configurar dos redes LAN distintas conectadas por un router, verificar que el router actúa como gateway de cada una, observar el proceso ARP en acción, y confirmar cómo el router enruta el tráfico entre ambas redes usando su tabla de enrutamiento.

1. Materiales necesarios

  • Cisco Packet Tracer (versión 8.x o superior)
  • 4 PC de escritorio (PC-PT)
  • 2 Switches (2960)
  • 1 Router con 2 interfaces FastEthernet (1841 o ISR genérico)
  • Cables rectos (Copper Straight-Through)

2. Topología a construir

  • Red A (192.168.1.0/24): PC0 y PC1 conectados a Switch0, Switch0 conectado a Fa0/0 del Router0
  • Red B (192.168.2.0/24): PC2 y PC3 conectados a Switch1, Switch1 conectado a Fa0/1 del Router0

3. Guía paso a paso

1
Armar la topología

Colocá los dispositivos y conectalos según el punto 2 con cable recto.

2
Configurar el router como gateway de ambas redes

En Router0 → CLI:

enable
configure terminal
interface FastEthernet0/0
ip address 192.168.1.1 255.255.255.0
no shutdown
exit
interface FastEthernet0/1
ip address 192.168.2.1 255.255.255.0
no shutdown

3
Configurar los PCs con su gateway correspondiente

PC0 y PC1 (Red A): IP dentro de 192.168.1.0/24, Gateway 192.168.1.1.
PC2 y PC3 (Red B): IP dentro de 192.168.2.0/24, Gateway 192.168.2.1.

4
Verificar la tabla ARP antes de comunicarse

En PC0 → Desktop → Command Prompt, ejecutá arp -a. La tabla debería estar vacía o casi vacía (todavía no se resolvió ninguna MAC).

5
Generar tráfico local y revisar ARP de nuevo

Hacé ping 192.168.1.[IP de PC1] desde PC0. Volvé a ejecutar arp -a: ahora debería aparecer la dirección MAC de PC1, resuelta mediante ARP.

6
Probar conectividad entre redes distintas

Desde PC0 (Red A), hacé ping a la IP de PC2 (Red B). Debería funcionar, atravesando el router. Ejecutá arp -a en PC0 nuevamente: vas a ver que aparece la MAC del gateway (192.168.1.1), no la de PC2 — confirmando que ARP solo resuelve dispositivos locales.

7
Inspeccionar la tabla de enrutamiento

En Router0 → CLI, ejecutá show ip route. Deberías ver ambas redes (192.168.1.0/24 y 192.168.2.0/24) como redes conectadas directamente (marcadas con "C").

8
Capturar el recorrido del paquete en modo Simulation

Cambiá a modo Simulation y enviá un ping de PC0 a PC2. Seguí el paquete paso a paso: notá cómo la dirección IP de destino nunca cambia, pero la dirección MAC de destino sí cambia en cada salto (primero la del gateway, luego la de PC2 dentro de la Red B).

4. Checklist de verificación final

0 / 6 pasos completados

5. Preguntas de reflexión

1. ¿Por qué la tabla ARP de PC0 muestra la MAC del gateway y no la de PC2, si el ping sí llegó correctamente a destino?
2. En el modo Simulation, ¿qué cambió y qué se mantuvo igual en el paquete a medida que viajaba de PC0 a PC2?
3. Si el router no tuviera configurada la interfaz Fa0/1, ¿qué pasaría al intentar hacer ping desde PC0 hacia PC2?
