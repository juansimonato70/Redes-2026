14.1 Seguridad de Red

14.1.0 Introducción

La seguridad de red implica implementar múltiples capas de defensa para proteger la integridad, confidencialidad y disponibilidad de datos y recursos de red.

Defensa en Profundidad (Defense in Depth)

No confiar en una sola medida de seguridad. Implementar múltiples capas:

  • Capa 1: Políticas y procedimientos
  • Capa 2: Seguridad física (acceso controlado a servidores)
  • Capa 3: Perímetro de red (firewalls, IPS)
  • Capa 4: Seguridad de red interna (segmentación, VLANs)
  • Capa 5: Seguridad de host (antivirus, host firewall)
  • Capa 6: Seguridad de aplicaciones (código seguro, WAF)
  • Capa 7: Seguridad de datos (cifrado, backups)

Principio: Si un atacante supera una capa, hay otras que lo detienen

14.1.1 Fundamentos de Seguridad

Principios Fundamentales

1. Least Privilege (Menor Privilegio)

Dar solo los permisos mínimos necesarios para hacer el trabajo

  • Usuario normal NO necesita ser administrador
  • Aplicación NO necesita acceso root
  • Reduce daño si cuenta es comprometida

2. Need-to-Know (Necesidad de Saber)

Acceso a información solo si es necesario para el rol

  • Finanzas no necesita acceso a datos de RRHH
  • Segmentación de datos por departamento

3. Defense in Depth (Defensa en Profundidad)

Múltiples capas de seguridad superpuestas

4. Fail Secure (Fallar de Forma Segura)

Si sistema falla, debe fallar en estado seguro (denegar acceso por defecto)

5. Separation of Duties (Separación de Funciones)

Ninguna persona debe tener control total de proceso crítico

  • Ejemplo: Una persona solicita pago, otra lo aprueba, tercera lo ejecuta
  • Previene fraude interno

Tipos de Controles de Seguridad

Tipo Propósito Ejemplos
Preventivos Prevenir que ocurra incidente Firewall, cifrado, autenticación, locks físicos
Detectivos Detectar incidente en progreso IDS, SIEM, logs, cámaras de seguridad
Correctivos Corregir después del incidente Restore desde backup, parches, reinstalar
Disuasivos Disuadir de intentar ataque Avisos legales, cámaras visibles, guardias
Compensatorios Alternativa cuando control principal no es posible Si no hay 2FA, usar contraseña extra fuerte

14.1.2 Control de Acceso

Autenticación (Authentication)

Definición: Verificar identidad del usuario

Factores de autenticación:

  • Algo que SABES: Contraseña, PIN, respuestas secretas
  • Algo que TIENES: Token, smart card, teléfono móvil
  • Algo que ERES: Huella digital, iris, reconocimiento facial
  • Algo que HACES: Patrones de tecleo, firma
  • DÓNDE ESTÁS: Geolocalización, dirección IP

Autenticación Multifactor (MFA / 2FA)

Definición: Requiere 2+ factores DIFERENTES de autenticación

Ejemplos:

  • 2FA típico: Contraseña (saber) + Código SMS (tener)
  • Banking: Tarjeta (tener) + PIN (saber)
  • Oficina segura: Badge (tener) + Huella (ser)

NO es MFA:

  • Contraseña + Pregunta secreta (ambos "algo que sabes")
  • Requiere factores de DIFERENTES categorías

Beneficio: Aunque roben tu contraseña, atacante no tiene tu teléfono

Métodos Comunes de Autenticación

  • Local: Usuario/contraseña almacenados en el dispositivo
  • RADIUS: Servidor central de autenticación (común para WiFi empresarial)
  • TACACS+: Similar a RADIUS, más usado para dispositivos de red
  • Kerberos: Autenticación con tickets (usado en Active Directory)
  • LDAP: Directorio centralizado (ej: Active Directory)
  • SSO (Single Sign-On): Una autenticación para múltiples servicios
  • OAuth / SAML: Autenticación delegada ("Login con Google")

Autorización (Authorization)

Definición: Determinar QUÉ puede hacer el usuario autenticado

Después de autenticación exitosa, verificar permisos

Modelos de Control de Acceso:

  • DAC (Discretionary Access Control):
    • Dueño del recurso decide quién tiene acceso
    • Ejemplo: Permisos de archivos en Windows/Linux
  • MAC (Mandatory Access Control):
    • Sistema operativo controla acceso basado en niveles de seguridad
    • Usuario no puede cambiar permisos
    • Usado en ambientes militares/gubernamentales
  • RBAC (Role-Based Access Control):
    • Permisos basados en roles (Manager, Employee, Admin)
    • Más fácil de administrar que dar permisos individuales
    • Muy común en empresas

Accounting (Registro/Auditoría)

Definición: Registrar QUÉ hizo el usuario

  • Logs de acceso (cuándo, desde dónde)
  • Logs de actividad (qué archivos abrió, qué comandos ejecutó)
  • Rastro de auditoría para investigaciones
  • Compliance con regulaciones (SOX, HIPAA, GDPR)

AAA (Authentication, Authorization, Accounting)

Framework completo de control de acceso:

  1. Authentication: ¿Quién eres? (Verificar identidad)
  2. Authorization: ¿Qué puedes hacer? (Verificar permisos)
  3. Accounting: ¿Qué hiciste? (Registrar acciones)

14.1.3 Defensa de Sistemas y Dispositivos

Hardening (Endurecimiento) de Sistemas

Definición: Reducir superficie de ataque del sistema

Medidas de hardening:

  • Actualizar y parchear:
    • Mantener OS y aplicaciones actualizados
    • Parches de seguridad mensuales (Patch Tuesday de Microsoft)
  • Deshabilitar servicios innecesarios:
    • Menos servicios corriendo = menos vectores de ataque
    • Si no usas FTP, deshabilitarlo
  • Remover software innecesario:
    • Software no usado puede tener vulnerabilidades
  • Configuración segura:
    • Cambiar contraseñas por defecto (admin/admin)
    • Deshabilitar cuentas guest
    • Configurar complejidad de contraseñas
  • Cifrado:
    • Cifrar disco duro (BitLocker, FileVault)
    • Cifrar datos en tránsito (HTTPS, VPN)
  • Logs y monitoreo:
    • Habilitar logging detallado
    • Monitorear eventos sospechosos

14.1.4 Protección de Antimalware

Antivirus / Antimalware

Cómo funciona:

  • Detección basada en firmas:
    • Base de datos de "firmas" de malware conocido
    • Compara archivos contra base de datos
    • Limitación: Solo detecta malware conocido
    • Requiere actualizaciones constantes
  • Detección heurística:
    • Analiza comportamiento del programa
    • ¿Intenta modificar archivos de sistema?
    • ¿Se comunica con IPs sospechosas?
    • Puede detectar malware nuevo (zero-day)
  • Sandboxing:
    • Ejecutar archivo sospechoso en entorno aislado
    • Observar qué hace sin riesgo

Limitaciones:

  • No es 100% efectivo
  • Puede generar falsos positivos
  • Consume recursos del sistema
  • Malware sofisticado puede evadir detección

Soluciones populares:

  • Windows Defender (integrado en Windows)
  • Symantec Endpoint Protection
  • McAfee, Kaspersky, Bitdefender
  • Malwarebytes (especializado en malware)

14.1.5 Firewalls y Prevención de Intrusiones Basada en Host

Host-Based Firewall (Firewall de Host)

Definición: Firewall en cada dispositivo individual

Función: Controlar tráfico entrante/saliente del dispositivo

Ejemplos:

  • Windows Firewall (integrado en Windows)
  • iptables / firewalld (Linux)
  • Little Snitch (macOS)

Configuración típica:

  • Bloquear todo entrante por defecto
  • Permitir saliente (con excepciones)
  • Crear reglas para aplicaciones específicas

HIPS (Host-based Intrusion Prevention System)

Definición: Sistema que detecta y previene actividad maliciosa en el host

Diferencia con antivirus:

  • Antivirus: Escanea archivos
  • HIPS: Monitorea comportamiento en tiempo real

Qué protege:

  • Buffer overflows
  • Escalación de privilegios
  • Modificaciones no autorizadas a archivos de sistema
  • Inyección de código

14.1.6 Acceso Inalámbrico Seguro

La seguridad del punto de acceso (protocolo WPA usado, contraseña) protege toda la red inalámbrica

Protocolos de Seguridad WiFi

Protocolo Año Seguridad Estado
WEP 1997 Muy débil ❌ Obsoleto, NO USAR
WPA 2003 Débil ❌ Deprecated
WPA2 2004 Buena ✅ Aceptable (mínimo)
WPA3 2018 Excelente ✅ Recomendado

Mejores Prácticas de Seguridad WiFi

  • Usar WPA3 (o mínimo WPA2): WEP/WPA son crackeables en minutos
  • Contraseña fuerte: Mínimo 12 caracteres, mezcla de mayúsculas/minúsculas/números/símbolos
  • Cambiar SSID por defecto: No usar "NETGEAR" o "Linksys"
  • Deshabilitar WPS: Vulnerable a ataques de fuerza bruta
  • Deshabilitar administración remota: Solo configurar desde LAN
  • Actualizar firmware del router: Parches de seguridad
  • Red Guest separada: Para visitantes, aislada de red interna
  • Filtrado MAC (opcional): Permite solo MACs conocidas (fácil de bypassear, pero añade capa)
  • Deshabilitar SSID broadcast (opcional): Red oculta (seguridad por oscuridad, no muy efectiva)
  • Considerar 802.1X / RADIUS: Para empresas, autenticación por usuario

Segmentación de Red Inalámbrica

Principio: Separar diferentes tipos de tráfico/usuarios

VLANs típicas:

  • VLAN Empleados: Acceso a recursos internos
  • VLAN Invitados: Solo Internet, sin acceso interno
  • VLAN IoT: Dispositivos inteligentes aislados
  • VLAN BYOD: Dispositivos personales de empleados

Beneficio: Si un dispositivo es comprometido, no puede acceder a toda la red
